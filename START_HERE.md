## FIRE Core model now under real-use proof

`FIRE_CORE.md` is canonical for the detailed doctrine. Current Core behavior being proven is intentionally thinner than the eventual product.

Production domains:

**Material & Form → Arrangement & Roles → Source & Performance → Capture & Construction → Edit & Assembly → Balance & Hierarchy → Tone & Dynamics → Space & Movement → Translation & Finish**

This is dependency/orientation, not a compulsory sequence.

Active Focus chooses the highest-value current problem/opportunity using current target, project knowledge, production knowledge, constraints, dependencies, and new evidence.

The FIRE loop operates inside that focus:

**Feel → Identify → Reason → Experiment → Evaluate**

Questions are supporting evidence collection only. FIRE should not ask when the answer is already known, inferable, available from a Recreation reference/incoming context, better discovered through a small DAW experiment, or irrelevant to the next useful recommendation.

The underlying engine may be information-rich. The musician experience should remain information-light.

## Definition of the current proof succeeding

The proof succeeds when a musician can physically do:

**Open song → understand what FIRE thinks deserves attention → understand why → receive one useful DAW action → leave FIRE → return with what happened → FIRE remembers the result → FIRE's next recommendation changes for a clear reason**

without walking through the old fixture, filling out a profile, or spending more effort maintaining FIRE than making the record.

If that works for both the Cover and `Even`, FIRE Core has begun to exist as product behavior rather than architecture discussion.
